---
title: 自动更新镜像
description: 让 Redis、PostgreSQL 这类服务在你选的时段自动换成新的补丁版本，失败时自动回滚。
---

开启后，服务会在你选的时段里，自动换成同一版本的最新补丁版本，例如 `redis:7.2.4` 换成 `redis:7.2.5`。新副本没有启动成功，就自动回滚到原来的版本，之后不会再试那个版本。新的次版本或主版本不会自动更换，会在服务的**设置**里提醒你。

## 开始前

- 集群管理员要在 Zeabur 的 Helm chart 开启 `imageUpdates.enabled`。没有开启时，这里的设置会保留，但不会更新任何东西。
- 服务是 Deployment 或 StatefulSet，只有一个容器，镜像标签是 `X.Y.Z` 这种格式，例如 `redis:7.2.4` 或 `redis:7.2.4-alpine`。
- 由 Helm、Argo CD、Flux 或数据库 operator 管理的服务不能在这里开启，请在那个工具里更新镜像。从 Git 构建、开启**新构建完成后自动部署**的服务，也由那个设置负责。
- 有权限修改项目中的服务。

## 开启自动更新

<Steps>
<Step>

### 选择时段

打开服务的**设置**，找到**自动更新到新的补丁版本**。选择**日期**、**开始时间**、**持续**多久，以及**时区**。时区使用 IANA 名称，例如 `Asia/Shanghai` 或 `Europe/Amsterdam`；夏令时会按时区自动调整。

</Step>
<Step>

### 打开开关

打开开关，确认检查页面后应用。之后每到时段，就会检查一次镜像仓库有没有新的补丁版本。

</Step>
<Step>

### 查看结果

开关下方会说明上次做了什么：已更新到哪个版本、没有更新的补丁版本，或某个版本因为卡住而回滚。有新的次版本或主版本时，也会在这里提醒你。

</Step>
</Steps>

要更改时段，改好字段后点击**更改时段**。要停止自动更新，关闭开关。

## 更新的过程

1. 时段开始后，读取镜像仓库的标签，选出同一版本的最新补丁版本。每个时段只检查一次。
2. 换上新的镜像，接着跟踪部署进度，和服务**概览**里的**部署进度**相同。
3. 新副本都就绪就完成。新副本反复崩溃、拉取不到镜像，或超过期限还没就绪，就回滚到原来的版本，之后不会再试这个版本。

部署失败时，也会和其他部署一样通知项目的通知渠道（例如 Webhook 或 Slack）。在项目的**设置** → **通知**中添加渠道，并选择部署和反复崩溃的事件（[通知](../cluster/notifications.mdx)）。

## 用 kubectl 设置

这个设置写在工作负载的一个 label 和一个 annotation 上。以下以项目 `demo` 的 StatefulSet `redis` 为例：

```sh
kubectl -n demo label statefulset redis zeabur.com/image-updates=patch
kubectl -n demo annotate statefulset redis zeabur.com/image-update-window='sun 03:00 2h Asia/Shanghai'
```

时段的格式是 `<日期> <开始时间> <持续> <时区>`：日期是 `daily` 或用逗号分隔的 `mon` 到 `sun`，持续时间从 `15m` 到 `24h`。更新程序把上次的结果写在 `zeabur.com/image-update-status` annotation 里。

## 故障排查

| 你看到的情况 | 下一步 |
| --- | --- |
| 开启了，但从来没有检查 | 请集群管理员确认 Zeabur 的 chart 开启了 `imageUpdates.enabled`。 |
| “部署卡住了…已换回…” | 新版本在这个服务上没有启动。查看**日志**找原因；这个版本不会再试，下一个补丁版本发布时才会再更新。 |
| “…已发布”但没有更新 | 那是新的次版本或主版本，要由你决定。准备好时在**设置**里更换镜像。 |
| 开启时提示镜像没有 X.Y.Z 标签 | 先把镜像换成有完整版本号的标签，例如 `redis:7.2.4`，而不是 `redis:7` 或 `latest`。 |
