---
title: 自動更新映像檔
description: 讓 Redis、PostgreSQL 這類服務在你選的時段自動換成新的修補版本，失敗時自動回滾。
---

開啟後，服務會在你選的時段裡，自動換成同一版本的最新修補版本，例如 `redis:7.2.4` 換成 `redis:7.2.5`。新副本沒有啟動成功，就自動回滾到原本的版本，之後不會再試那個版本。新的次要版本或主要版本不會自動換，會在服務的**設定**裡提醒你。

## 開始前

- 叢集管理員要在 Zeabur 的 Helm chart 開啟 `imageUpdates.enabled`。沒開啟時，這裡的設定會保留，但不會更新任何東西。
- 服務是 Deployment 或 StatefulSet，只有一個容器，映像檔標籤是 `X.Y.Z` 這種格式，例如 `redis:7.2.4` 或 `redis:7.2.4-alpine`。
- 由 Helm、Argo CD、Flux 或資料庫 operator 管理的服務不能在這裡開啟，請在那個工具裡更新映像檔。從 Git 建置、開啟**新建置完成後自動部署**的服務，也由那個設定負責。
- 有權修改專案裡的服務。

## 開啟自動更新

<Steps>
<Step>

### 選擇時段

打開服務的**設定**，找到**自動更新到新的修補版本**。選擇**日期**、**開始時間**、**持續**多久，以及**時區**。時區用 IANA 名稱，例如 `Asia/Taipei` 或 `Europe/Amsterdam`；夏令時間會依時區自動調整。

</Step>
<Step>

### 開啟開關

開啟開關，確認檢查畫面後套用。之後每到時段，就會檢查一次映像檔倉庫有沒有新的修補版本。

</Step>
<Step>

### 查看結果

開關下方會說明上次做了什麼：已更新到哪個版本、沒有更新的修補版本，或某個版本因為卡住而回滾。有新的次要版本或主要版本時，也會在這裡提醒你。

</Step>
</Steps>

要換時段，改好欄位後按**變更時段**。要停止自動更新，關掉開關。

## 更新的過程

1. 時段開始後，讀取映像檔倉庫的標籤，挑出同一版本的最新修補版本。每個時段只檢查一次。
2. 換上新的映像檔，接著追蹤部署進度，和服務**概覽**裡的**部署進度**相同。
3. 新副本都就緒就完成。新副本反覆崩潰、拉不到映像檔，或超過期限還沒就緒，就回滾到原本的版本，之後不會再試這個版本。

部署失敗時，也會和其他部署一樣通知專案的通知管道（例如 Webhook 或 Slack）。在專案的**設定** → **通知**新增管道，並選擇部署和反覆崩潰的事件（[通知](../cluster/notifications.mdx)）。

## 用 kubectl 設定

這個設定寫在工作負載的一個 label 和一個 annotation 上。以下用專案 `demo` 的 StatefulSet `redis` 為例：

```sh
kubectl -n demo label statefulset redis zeabur.com/image-updates=patch
kubectl -n demo annotate statefulset redis zeabur.com/image-update-window='sun 03:00 2h Asia/Taipei'
```

時段的格式是 `<日期> <開始時間> <持續> <時區>`：日期是 `daily` 或用逗號分隔的 `mon` 到 `sun`，持續時間從 `15m` 到 `24h`。更新程式把上次的結果寫在 `zeabur.com/image-update-status` annotation 裡。

## 疑難排解

| 你看到的狀況 | 下一步 |
| --- | --- |
| 開啟了，但從來沒有檢查 | 請叢集管理員確認 Zeabur 的 chart 開啟了 `imageUpdates.enabled`。 |
| 「部署卡住了…已換回…」 | 新版本在這個服務上沒有啟動。查看**記錄**找原因；這個版本不會再試，下一個修補版本推出時才會再更新。 |
| 「…已推出」但沒有更新 | 那是新的次要版本或主要版本，要由你決定。準備好時在**設定**換映像檔。 |
| 開啟時說映像檔沒有 X.Y.Z 標籤 | 先把映像檔換成有完整版本號的標籤，例如 `redis:7.2.4`，而不是 `redis:7` 或 `latest`。 |
